# 블로그 포스트 검수 스킬

작성이 완료된 초안을 받아 아래 체크리스트 항목을 순서대로 점검한다.
초안이 대화 내에 없으면 "검수할 초안을 붙여넣어 주세요." 한 줄로 요청한다.

---

## 체크리스트 항목

### 1. 주제 집중도 (Focus)

- 포스트가 **단일 핵심 주제** 하나를 깊이 다루는가?
- 섹션이 3개 이상의 독립적인 기술 개념을 병렬로 다루고 있다면 분리를 권고한다.
- 판단 기준: "이 글의 핵심 한 줄 요약이 가능한가?" — 가능하면 통과, 두 문장 이상이 필요하면 경고.

### 2. 예제 충분성 (Examples)

- 본문에 **코드 블록 또는 실행 가능한 예시**가 최소 1개 이상 포함되어 있는가?
- 예제가 추상적(의사 코드 수준)이 아니라 **실제 프로젝트에 바로 사용 가능한** 형태인가?
- "실무 활용 사례" 섹션이 존재하는가? (draft-blog-post 스킬 기준 필수 항목)

### 3. 기술 용어 일관성 (Terminology)

한국어·영어 혼용 여부를 검사한다. 규칙:

- **한국어 설명 + 영어 괄호 병기** 형식이어야 한다: `요청 라인(Request Line)` ✅
- 같은 개념을 어떤 곳에서는 한국어, 다른 곳에서는 영어로만 표기하면 경고한다.
- 동일 용어가 포스트 내에서 두 가지 이상의 표기로 혼용되는 경우 목록을 뽑아 보여준다.

예시 경고 패턴:
- `캐싱`과 `Caching`이 혼용 → "캐싱(Caching)"으로 통일 권고
- `컴포넌트`와 `Component`가 혼용 → "컴포넌트(Component)"로 통일 권고

### 4. 문체 일관성 (Tone)

- 어미가 `-입니다 / -합니다 / -됩니다` 격식체로 일관되는가?
- `-해요 / -이에요 / -죠 / -거든요` 등 비격식체가 섞여 있으면 해당 문장을 인용해 지적한다.

### 5. 구조 완결성 (Structure)

draft-blog-post 스킬이 정의한 구조 기준으로 점검한다:

| 항목 | 기준 |
|------|------|
| 인트로 | H1 없이 바로 시작, 실무 상황으로 오프닝 |
| 섹션 구분 | `---` 구분선 존재 |
| Reference | 마지막 섹션으로 존재 |
| 메타 정보 | 제목 / 설명 / 카테고리 제안 포함 |

### 6. 가독성 (Readability)

- 단락 하나가 5문장을 초과하면 분리 권고.
- 연속된 3개 이상의 bullet list가 코드 블록·표 없이 나열되면 표나 섹션으로 재구성 권고.
- H2 섹션이 단락 없이 곧바로 bullet list로만 구성된 경우 짧은 도입 문장 추가 권고.

## 출력 형식

점검 결과는 아래 형식으로 출력한다:

```
## 블로그 포스트 검수 결과

### ✅ / ⚠️ / ❌  1. 주제 집중도
[통과 | 경고 | 실패] — 한 줄 판정 이유

### ✅ / ⚠️ / ❌  2. 예제 충분성
...

### ✅ / ⚠️ / ❌  3. 기술 용어 일관성
혼용 용어 목록 (없으면 "이상 없음"):
- ...

### ✅ / ⚠️ / ❌  4. 문체 일관성
비격식체 문장 (없으면 "이상 없음"):
- ...

### ✅ / ⚠️ / ❌  5. 구조 완결성
누락 항목 (없으면 "이상 없음"):
- ...

### ✅ / ⚠️ / ❌  6. 가독성
...

---

### 종합 의견
[전체 요약 — 2~3문장. 가장 우선으로 수정해야 할 항목을 언급한다.]
```

아이콘 기준:
- ✅ 통과 — 기준 충족
- ⚠️ 경고 — 작동하지만 개선 권장
- ❌ 실패 — 게시 전 반드시 수정 필요

---

## 주의사항

- 스타일 취향(단어 선택, 설명 깊이 등)은 지적하지 않는다. 명확한 규칙 위반만 다룬다.
- 수정 예시는 필요한 경우에만 간결하게 제시한다. 긴 재작성은 하지 않는다.
- 검수 완료 후 "수정이 필요한 항목을 반영해 업데이트할까요?" 한 줄로 마무리한다.
