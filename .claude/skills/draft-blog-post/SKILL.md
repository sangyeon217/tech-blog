# 블로그 초안 작성 스킬

사용자의 기술 블로그(sangyeon217.vercel.app)는 한국어로 작성된 웹/프론트엔드 기술 블로그다.
기존 글들을 분석해 추출한 문체 패턴을 완전히 재현해 초안을 작성한다.

**핵심 문체 방향**: 직설적이고 실용적. 이론보다 실무 중심. 개념 설명에 머물지 않고 "실제로 어디에 쓰이는가", "어떻게 적용하는가"를 항상 보여준다.

## 사전 확인

주제가 제시되지 않았거나 너무 광범위하면 아래 두 가지를 간단히 물어본다:

1. **주제**: 어떤 개념/기술을 다룰 것인가?
2. **카테고리**: web / javascript / react / css / 기타

주제가 충분히 구체적이면 바로 초안 작성에 들어간다. 불필요하게 많은 질문을 하지 않는다.

---

## 문체 및 구조 가이드

### 인트로 (제목 없음)

첫 단락은 독자가 바로 공감할 수 있는 **실무 상황**으로 시작한다. 추상적 정의나 "이 글에서는..."으로 시작하지 않는다.
H1 섹션 제목 없이 본문 바로 시작한다.

예시 패턴:
- "웹에서 발생하는 거의 모든 동작은 **[핵심 개념]** 으로 이루어집니다."
- "**[용어]** 는 처음 마주치면 복잡해 보이지만, 알고 나면 단순합니다."
- "브라우저 개발자 도구를 열어본 적이 있다면 [현상]을 본 적이 있을 것입니다."

인트로 마지막 문장은 이 글에서 다룰 내용을 한 줄로 예고한다:
"이 글에서는 [주제]의 개념부터 [심화 내용]까지 다룹니다."

### 본문 구조

```
인트로 단락 (H1 없이)

---

# 개념 정의 및 배경

## 왜 이런 구조가 생겼는가 (역사적/기술적 맥락)

---

# 핵심 구성요소

## 구성요소 1
## 구성요소 2
...

---

# 실제 예제

---

# 실무 활용 사례 (선택)

---

# Reference
```

- H1(`#`)으로 주요 섹션 구분
- H2(`##`)로 세부 항목 구분
- H3(`###`)은 H2 하위의 추가 분류에만 사용
- 섹션 사이에 `---` 구분선 삽입
- 마지막은 반드시 `# Reference` 섹션으로 마무리

---

### 한국어 문체 규칙

**어미**: `-입니다 / -합니다 / -됩니다` 격식체 사용. `-해요 / -이에요` 사용 금지.

**기술 용어 표기**: 한국어 설명을 먼저 쓰고 영어를 괄호로 병기한다.
- ✅ `요청 라인(Request Line)`, `상태 코드(Status Code)`
- ❌ `Request Line(요청 라인)`

**개인 경험**: 독자가 직접 실험할 수 있는 방법을 제시하거나, 자연스럽게 개인 경험을 짧게 녹인다.
- "Chrome 개발자 도구 콘솔에서 직접 확인할 수 있습니다."
- "제 맥북 Chrome에서 확인한 결과는 다음과 같습니다."
- "(저는 가끔 이 방법을 활용하곤 합니다. 😄)"

**단락 길이**: 한 단락은 3~5문장 내외. 길어지면 내용이 다른 문단으로 분리한다.

### 포맷 규칙

| 요소 | 사용 방법 |
|------|-----------|
| `**볼드**` | 핵심 개념, 중요 용어 첫 등장 시 |
| `` `인라인 코드` `` | HTTP 메서드, 속성명, 값, 파일명 |
| 코드 블록 | 실제 코드/명령어 — 언어 반드시 지정 (js/ts/bash/http/json/text/html/css) |
| `>` 인용문 | 참고사항, 주의사항, 보충 설명 |
| 표(Table) | 비교, 목록화가 필요한 항목 |

**코드 블록 언어 지정 원칙**:
- 명령어 → `bash`
- HTTP 요청/응답 → `http`
- 출력 결과 → `text`
- 개념적 흐름 → `text`

### 내용 구성 패턴

1. **개념 정의**: 한 문장으로 핵심을 정의 + 독자가 이 개념을 왜 알아야 하는지
2. **배경/맥락**: "왜 이렇게 만들어졌는가" 역사적·기술적 이유 (독자의 "왜?" 해소)
3. **구성요소 분해**: 전체를 부분으로 나누어 각각 설명, 코드/표/예시 첨부
4. **실제 예제**: 독자가 바로 실행해볼 수 있는 코드나 명령어
5. **실무 활용 사례**: 이 개념이 실제 서비스/개발에서 어떻게 쓰이는지 — **필수**, 선택 아님
6. **Reference**: 출처 URL 목록

**실무 중심 원칙**:
- 개념 설명 후 반드시 "실제로 어떤 상황에서 마주치는가", "어떻게 적용하는가"를 다룬다
- 역사적 배경은 짧게 — 이론 강의가 아닌 실무 가이드를 지향한다
- "이론적으로는..." 같은 우회 표현 대신 직접 결론부터 말한다
- 코드 예제는 실제 프로젝트에서 바로 쓸 수 있는 형태로 작성한다

## 출력 방식

- 마크다운 형식으로 전체 초안을 출력한다
- Contentful에 자동 업로드하지 않는다
- 초안 생성 후 "이 초안을 기반으로 수정할 부분이 있으면 말씀해 주세요." 한 줄로 마무리
- 초안 앞에 메타 정보를 별도로 제안한다:

```
**제목(title)**: [제안 제목]
**설명(description)**: [한 줄 요약 — 블로그 카드에 표시될 문장]
**카테고리**: [web / javascript / react / 기타]
```
